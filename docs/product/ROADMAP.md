# ROADMAP

Version: 1.0

Status: Accepted

This document defines the long-term capability evolution of the product.

This is accepted doctrine.

---

## 1. Purpose Of This Document

ROADMAP.md defines how the product should evolve as a system of compounding capabilities.

It does not define releases, quarters, milestones, features, engineering work, implementation sequence, or delivery commitments.

Its purpose is to describe the capability layers the product must develop over time in order to increase human financial decision capability.

Every capability exists because it strengthens the user's ability to understand, judge, and decide.

No capability exists merely because it is possible to build.

---

## 2. Relationship To Constitutional Layer

The roadmap inherits from the accepted constitutional and strategic documents:

```text
PRODUCT_MANIFESTO.md
        -> why we exist

PRODUCT_PRINCIPLES.md
        -> how we make product decisions

PRODUCT_STRATEGY.md
        -> how we compete

ROADMAP.md
        -> how product capabilities should evolve
```

The roadmap must remain faithful to:

- human judgement strengthened, never replaced
- deterministic truth before interpretation
- privacy as architecture
- user agency as final authority
- survival before optimization
- recommendations grounded in evidence
- capability over dependence
- the strategic North Star: increase retained financial decision capability

If this roadmap conflicts with the Manifesto, Principles, or Strategy, those documents prevail.

---

## 3. Roadmap Philosophy

This roadmap is not a list of things to ship.

It is a doctrine for capability evolution.

The product should not accumulate features.

It should compound human capability.

Each capability layer should permanently strengthen the layers beneath it.

Each new capability should make previous capabilities more valuable, clearer, and more trustworthy.

Capability should compound.

Complexity must not.

The product evolves correctly when each layer increases the user's ability to understand financial reality, recognize trade-offs, act responsibly, and learn from decisions over time.

The product evolves incorrectly when each layer adds surface area, attention cost, data exposure, or automation without increasing judgement.

The roadmap should therefore be read as a maturity model:

- not a release plan
- not a feature backlog
- not a sprint sequence
- not an engineering architecture
- not a promise of delivery timing

Later capabilities may be explored before earlier capabilities are perfect.

However, no capability should become strategically central before the capabilities beneath it are trustworthy enough to support it.

---

## 4. Capability Evolution Model

The product should evolve through ten capability layers:

```text
Financial Reality Foundation
        ↓
Monthly Decision Clarity
        ↓
Risk And Constraint Intelligence
        ↓
Financial Memory
        ↓
Recommendation Intelligence
        ↓
Narrative And Story Intelligence
        ↓
Scenario And Decision Simulation
        ↓
Forecast And Resilience Intelligence
        ↓
Ecosystem-Aware Decision Layer
        ↓
Human Capability System
```

This is a dependency model, not a delivery schedule.

Each layer answers:

- why the capability exists
- what new human capability it unlocks
- what it depends on
- what previous capabilities it strengthens
- what strategic purpose it serves
- what it must not become

---

## 5. Layer 1 — Financial Reality Foundation

**Why this capability exists**

The user cannot make sound financial decisions unless their financial reality is represented clearly, deterministically, and with respect for privacy.

This layer establishes the product's truth foundation.

**New user capability unlocked**

The user can see their financial situation as something coherent enough to reason about.

**Depends On**

This is the first capability layer.

Every later layer depends on it.

**Strengthens**

This layer creates the evidence base that every future capability must respect.

It makes later clarity, memory, recommendations, stories, simulations, forecasts, and ecosystem connections accountable to reality.

**Strategic purpose**

Financial Reality Foundation makes the product trustworthy before it becomes intelligent.

It protects every future recommendation, story, simulation, forecast, and ecosystem connection from being built on unstable ground.

**What it must not become**

It must not become data collection for its own sake.

It must not confuse more data with more truth.

---

## 6. Layer 2 — Monthly Decision Clarity

**Why this capability exists**

Users need to understand what matters in the current month before they can act responsibly.

Financial facts must become decision context.

**New user capability unlocked**

The user can identify the next responsible monthly decision instead of facing disconnected numbers.

**Depends On**

It depends on Financial Reality Foundation to make the current situation understandable.

**Strengthens**

It strengthens Financial Reality Foundation by turning financial facts into attention priority.

It makes reality useful for near-term judgement rather than merely visible.

**Strategic purpose**

This layer begins the shift from financial dashboard to Financial Decision OS.

It turns information into attention priority.

**What it must not become**

It must not become a dense overview that consumes attention without improving judgement.

---

## 7. Layer 3 — Risk And Constraint Intelligence

**Why this capability exists**

Meaningful financial decisions happen under constraints.

The product must help users see obligations, timing pressure, liquidity limits, survival boundaries, and risk before suggesting action.

**New user capability unlocked**

The user can distinguish urgent from important, survivable from dangerous, and necessary risk from avoidable risk.

**Depends On**

It builds on Monthly Decision Clarity by showing which constraints shape the next responsible decision.

**Strengthens**

It strengthens Monthly Decision Clarity by showing which decisions are constrained by timing, liquidity, obligations, and survival boundaries.

It makes clarity more responsible.

**Strategic purpose**

This layer prevents recommendations from becoming optimistic, generic, or detached from financial pressure.

**What it must not become**

It must not become alarmism, shame, or dramatic risk theater.

Risk must create clarity, not panic.

---

## 8. Layer 4 — Financial Memory

**Why this capability exists**

No financial decision has complete meaning in isolation.

Memory helps the user and product understand patterns, changes, repeated constraints, and the consequences of prior decisions.

**New user capability unlocked**

The user can learn from continuity rather than only reacting to the current month.

**Depends On**

It depends on Financial Reality Foundation, Monthly Decision Clarity, and Risk And Constraint Intelligence.

Only trustworthy reality and meaningful risk context deserve to be remembered.

**Strengthens**

It strengthens Monthly Decision Clarity by making current decisions historically meaningful.

It strengthens Risk And Constraint Intelligence by revealing whether constraints are isolated, recurring, worsening, or improving.

**Strategic purpose**

Financial Memory transforms the product from a monthly analysis tool into a compounding decision system.

It creates the context required for better recommendations.

**What it must not become**

It must not become surveillance, profiling, or judgemental history.

Memory exists to strengthen understanding, not to possess the user.

---

## 9. Layer 5 — Recommendation Intelligence

**Why this capability exists**

Users need grounded guidance about what deserves attention next and why.

Recommendations should translate reality, constraints, and memory into decision support.

**New user capability unlocked**

The user can understand the next responsible action, the evidence behind it, and the trade-offs it creates.

**Depends On**

It depends on deterministic truth, monthly clarity, risk context, and financial memory.

Recommendation quality depends on accumulated context.

Context depends on memory.

**Strengthens**

It strengthens Risk And Constraint Intelligence by translating visible risk into responsible action.

It strengthens Financial Memory by making remembered patterns useful for present judgement.

**Strategic purpose**

This layer creates differentiated decision leverage while preserving user agency.

It is where the product begins helping users make better decisions, not merely understand their situation.

**What it must not become**

It must not become generic advice, AI opinion, opaque instruction, or automation disguised as guidance.

---

## 10. Layer 6 — Narrative And Story Intelligence

**Why this capability exists**

Users understand through sequence, context, and consequence.

Financial reality becomes more useful when the product can explain what changed, why it matters, and how it connects to decisions.

**New user capability unlocked**

The user can understand the story behind the numbers without losing fidelity to evidence.

**Depends On**

It depends on Financial Memory and Recommendation Intelligence.

No story should exist without remembered context and grounded interpretation.

**Strengthens**

It strengthens Financial Memory by turning historical facts into coherent understanding.

It strengthens Recommendation Intelligence by explaining why guidance matters in the user's broader financial story.

**Strategic purpose**

This layer helps the product transfer understanding, not merely display outputs.

It strengthens retained capability by making financial meaning easier to remember and use.

**What it must not become**

It must not become dramatization, persuasion, motivational content, or narrative detached from evidence.

---

## 11. Layer 7 — Scenario And Decision Simulation

**Why this capability exists**

Users need to examine possible choices before committing to them.

Simulation allows the user to compare consequences without surrendering responsibility.

**New user capability unlocked**

The user can rehearse decisions, compare trade-offs, and understand possible outcomes before acting.

**Depends On**

It depends on deterministic reality, risk context, memory, recommendations, and narrative clarity.

Without those layers, simulation becomes isolated calculation.

**Strengthens**

It strengthens Recommendation Intelligence by allowing judgement to be exercised before commitment.

It strengthens Risk And Constraint Intelligence by making the consequences of alternative paths visible.

**Strategic purpose**

This layer strengthens agency by making consequences visible before action.

It gives users a safer way to practice judgement.

**What it must not become**

It must not become prediction theater or a promise that the future can be known.

---

## 12. Layer 8 — Forecast And Resilience Intelligence

**Why this capability exists**

Users need to understand future pressure, fragility, and resilience while accepting that uncertainty remains.

Forecasting is valuable only when it improves preparation.

**New user capability unlocked**

The user can prepare for likely constraints and evaluate resilience without mistaking forecasts for guarantees.

**Depends On**

It depends on simulation, memory, risk intelligence, and deterministic truth.

Visible uncertainty must remain part of the capability.

**Strengthens**

It strengthens Scenario And Decision Simulation by preparing users for uncertainty rather than predicting certainty.

It strengthens Risk And Constraint Intelligence by showing how fragility and resilience may evolve over time.

**Strategic purpose**

This layer helps the user act responsibly before pressure becomes irreversible.

It turns future uncertainty into preparation rather than false certainty.

**What it must not become**

It must not become overconfident prediction, long-range certainty, or fear-based forecasting.

---

## 13. Layer 9 — Ecosystem-Aware Decision Layer

**Why this capability exists**

Financial lives span institutions, accounts, products, providers, and external systems.

The product must eventually help users reason across that ecosystem without becoming subordinate to it.

**New user capability unlocked**

The user can make decisions across institutions and systems while preserving one coherent decision layer.

**Depends On**

It depends on a trusted internal decision system.

External systems may improve evidence only after the product can preserve independent judgement.

**Strengthens**

It strengthens Financial Reality Foundation by improving evidence without surrendering independent judgement.

It strengthens every decision layer by expanding context across institutions while preserving the product's role as the user's decision layer.

**Strategic purpose**

This layer expands usefulness across the user's financial life while protecting the product's role as the independent decision layer.

**Permanent governance constraint**

No partner may distort recommendations.

No commercial relationship may influence user-facing judgement.

External institutions may improve evidence.

External institutions must never own, redirect, or subordinate the product's decision layer.

**What it must not become**

It must not become partner-led product direction, platform sprawl, institution-dependent judgement, or recommendations distorted by external incentives.

---

## 14. Layer 10 — Human Capability System

**Why this capability exists**

The constitutional purpose of the product is not to make the product indispensable.

It is to leave the person more capable.

**New user capability unlocked**

The user becomes permanently more capable of understanding financial reality, recognizing trade-offs, evaluating risk, and making responsible decisions than they were before using the product.

**Depends On**

It depends on every previous capability layer.

Truth, clarity, risk intelligence, memory, recommendations, narrative, simulation, forecasting, and ecosystem awareness should all compound into human capability.

**Strengthens**

It strengthens every previous layer because capability remains with the person rather than the product.

Each product capability becomes more valuable when the user can carry its lessons into future judgement.

**Strategic purpose**

This layer makes the strategic North Star visible.

It is the product's highest measure of maturity.

It represents stronger judgement, stronger responsibility, stronger ownership of consequences, and stronger independence from the product itself.

**What it must not become**

It must not become dependence disguised as success.

If the user becomes less capable without the product, the product has failed its constitutional purpose.

---

## 15. Capability Dependency Rules

These rules govern capability maturity.

They are constitutional rules, not engineering constraints.

- No capability without human agency.
- No recommendation without deterministic truth.
- No recommendation without risk context.
- No recommendation without memory when personal context matters.
- No memory without trust.
- No memory without privacy restraint.
- No story without memory.
- No story without evidence.
- No simulation without visible trade-offs.
- No forecast without visible uncertainty.
- No ecosystem without independence.
- No integration without user-aligned judgement.
- No automation before explanation.
- No growth before retained human capability.

When two capabilities conflict, the lower foundational capability must remain trustworthy before the higher capability expands.

---

## 16. What This Roadmap Refuses

This roadmap refuses to become:

- a feature roadmap
- a release plan
- a quarterly planning document
- an engineering backlog
- an implementation sequence
- a list of AI capabilities for novelty
- dashboard sprawl
- partner-led product direction
- automation before explanation
- forecasts before trust
- memory before dignity
- growth before human capability

The product should not become broader at the cost of becoming less capable.

The roadmap exists to protect capability evolution from feature accumulation.

---

## 17. Success Criteria For Capability Evolution

A capability layer is maturing when the user gains a durable new decision capability.

Success is not defined by shipping more surface area.

Success is visible when:

- the user understands their financial reality more clearly
- the user can identify the next responsible decision
- the user can see trade-offs before acting
- the user can explain why guidance exists
- the user can recognize risk without panic
- the user can learn from prior patterns
- the user can compare scenarios without false certainty
- the user can prepare for uncertainty without believing it has disappeared
- the user can reason across external systems without losing agency
- the user becomes more capable over time

The highest success condition is human capability that remains with the user.

---

## 18. Capability Readiness

Capability readiness is not release readiness.

It is constitutional readiness.

The product is ready to evolve into a new capability layer only when the new capability:

- increases retained human capability
- strengthens previous capability layers
- preserves user agency
- protects privacy and human dignity
- respects finite attention
- increases understanding rather than complexity
- improves judgement rather than automation
- remains faithful to deterministic truth
- preserves trust
- communicates uncertainty honestly
- remains faithful to PRODUCT_MANIFESTO.md
- remains consistent with PRODUCT_PRINCIPLES.md
- serves the competitive doctrine in PRODUCT_STRATEGY.md
- keeps truth, uncertainty, and trade-offs visible

A capability should not be introduced simply because it is technically possible, commercially attractive, or competitively fashionable.

Every new capability proposal must explicitly define:

- what it refuses to become
- which constitutional failure mode it introduces
- which previous capability it could weaken
- how it avoids unnecessary complexity

If a new capability weakens the layers beneath it, the product is not ready for that capability.

---

## 19. Roadmap Amendment Policy

ROADMAP.md may evolve as the product and market understanding mature.

It may change more often than PRODUCT_MANIFESTO.md, PRODUCT_PRINCIPLES.md, or PRODUCT_STRATEGY.md.

However, every amendment must remain consistent with the accepted constitutional and strategic documents.

Future changes require explicit versioned constitutional review.

Every amendment should answer:

- Which human decision capability does this change strengthen?
- Which previous capability layer does it depend on?
- Which previous capability layer does it strengthen?
- What complexity does it introduce?
- What user agency does it preserve?
- What constitutional risk does it create?
- Does it increase human capability, or merely expand product capability?

If a roadmap change creates feature accumulation without capability compounding, it should be rejected.

If a roadmap change weakens deterministic truth, privacy, user agency, or retained human capability, it should be rejected.
